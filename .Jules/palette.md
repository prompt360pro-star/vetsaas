## 2024-06-25 - Form Fields Accessibility (aria-describedby and id generation)
**Learning:** For interactive UI forms, it is critical to explicitly tie `<label>` tags with input fields (`<input>`, `<textarea>`, `<select>`) via `htmlFor` and unique `id`s. When generating fallback unique IDs (e.g., using `useId()`), ensure explicit IDs (`prop.id`) take precedence. Moreover, when using `aria-describedby` for error text vs hint text, it's critical to prioritize the validation error message so screen readers announce it accurately instead of muddying the text with hints. Decorative required asterisks (`*`) and icons should be silenced with `aria-hidden="true"`.
**Action:** When implementing custom form components or adjusting existing ones, always incorporate `useId()` to provide fallback `id`s, map `htmlFor` to the input element, and conditionally populate `aria-describedby` to prioritize error feedback over general hints while adding `aria-hidden="true"` to structural/decorative visual elements.
