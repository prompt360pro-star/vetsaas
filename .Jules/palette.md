## 2026-05-20 - Robust Form Accessibility with useId
**Learning:** We cannot assume developers will consistently provide unique `id` props to form components like `Input`, `Textarea`, and `Select`. Without IDs, `<label htmlFor>` bindings and `aria-describedby` associations for errors/hints fail, breaking screen reader navigation. Additionally, visual-only decorative elements (like icons or asterisks for required fields) are announced unnecessarily by screen readers if not explicitly hidden.
**Action:** In React UI components, always generate a fallback ID using `useId()` (`const id = propId || fallbackId`) to ensure `htmlFor` and `aria-describedby` are always perfectly linked. When conditionally setting attributes like `aria-describedby`, pass `undefined` rather than an empty string so React completely removes the attribute when it's not needed. Finally, always add `aria-hidden="true"` to decorative elements like icons or required asterisks to ensure clean accessible name computation.
