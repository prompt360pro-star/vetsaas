## 2024-12-21 - Accessible Form Controls and Decorative Elements
**Learning:** In reusable form components (Input, Textarea, Select), dynamically generating unique IDs using React's `useId()` (with fallback to explicitly provided `id`) is essential for robustly linking labels to inputs via `htmlFor`. When setting `aria-describedby` for validation, error messages should programmatically take priority over generic hint text, explicitly removing the hint from the accessible description computation when an error is present to prioritize validation feedback. Furthermore, visually meaningful required asterisks `*` and strictly decorative elements (like `lucide-react` icons in Buttons) must explicitly use `aria-hidden="true"` to prevent unnecessary noise for screen readers.
**Action:** Always utilize `useId()` in form primitives, conditionally construct `aria-describedby` prioritizing error states over hint states, and diligently apply `aria-hidden="true"` to visual-only indicators and icons to ensure clean accessible name and description computation.
