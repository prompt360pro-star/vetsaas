## 2024-05-28 - Missing label and description associations in standard form components
**Learning:** Found a recurring accessibility issue pattern in the app's foundational form components (`Input`, `Select`, `Textarea`). They lacked programmatic association between their labels and inputs (`htmlFor` -> `id`), and their error/hint messages were not linked to the inputs (`aria-describedby`), meaning screen readers would announce the input but not its label, current error, or helpful context. Additionally, visual-only required asterisks were being unnecessarily announced.
**Action:** When auditing or creating custom form components, always ensure: 1) `useId()` is used to generate a reliable fallback ID if none is provided; 2) The `<label>` and `<input>` (or `select`/`textarea`) are explicitly linked via `htmlFor`/`id`; 3) Any supplementary text (errors, hints) is assigned an ID and linked to the input via `aria-describedby`; and 4) Decorative elements like required asterisks have `aria-hidden="true"`.
