## 2024-05-15 - Form Component Accessibility Patterns
**Learning:** In reusable form components (Input, Textarea, Select), dynamically generating `id`s using React `useId()` and linking them via `htmlFor` is essential for screen reader context. Additionally, when managing `aria-describedby`, it is important to *exclude* hint text if an error is present, prioritizing validation feedback for screen readers. Furthermore, decorative visual markers like required asterisks (`*`) should include `aria-hidden="true"` to prevent screen readers from announcing them unnecessarily ("star"), ensuring a clean accessible name computation.
**Action:** When creating or updating form controls, always map labels to inputs with `useId`, set `aria-describedby` dynamically based on state hierarchy (errors > hints), and explicitly hide decorative visual elements with `aria-hidden="true"`.
