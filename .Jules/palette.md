## 2024-05-18 - Explicit Accessible Names for Custom Form Components
**Learning:** Custom UI components wrapping inputs (`Input`, `Textarea`, `Select`) often fail accessibility checks if the inner `<label>` isn't explicitly linked to the native `<input>` via `htmlFor` and `id`. While wrapping elements can implicitly link them, programmatic validation messages (errors, hints) require robust `aria-describedby` links. Utilizing React's `useId()` creates reliable fallback IDs when consumers don't explicitly pass an `id` prop, preventing DOM collisions on pages with multiple similar forms. Additionally, conditionally omitting `aria-describedby` (by passing `undefined` rather than an empty string) prevents React from rendering invalid empty ARIA attributes, and hiding visual required asterisks (`aria-hidden="true"`) keeps screen reader announcements clean.
**Action:** When creating or auditing form components, always generate fallback IDs using `useId()`, explicitly link labels with `htmlFor`, dynamically link validation states via `aria-describedby`, and mark decorative elements like icons and `*` as `aria-hidden="true"`.
