## 2024-05-17 - Accessible Form Bindings with Fallback IDs
**Learning:** In reusable React form UI components (like `Input`, `Textarea`, `Select`), developers often forget to pass explicit `id` props, which breaks the implicit `<label htmlFor>` to `<input id>` bindings required for screen readers. Similarly, error and hint messages need to be programmatically associated with inputs via `aria-describedby`, which requires IDs. Furthermore, decorative asterisks (`*`) used to indicate required fields should have `aria-hidden="true"` to prevent screen readers from announcing them as "star".
**Action:** When auditing or creating custom UI components, always implement `useId()` from React to generate a fallback unique identifier if `props.id` is not provided. Use this generated ID to correctly link the label's `htmlFor`, the input's `id`, and build derived IDs for `aria-describedby` associations (e.g., `${id}-error`). When passing `aria-describedby`, use a conditional array `.filter(Boolean).join(' ') || undefined` to cleanly handle multiple optional descriptive elements without leaving empty strings in the DOM. Finally, always add `aria-hidden="true"` to visual asterisks indicating required fields.
