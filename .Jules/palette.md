## 2024-06-02 - Form Field Label and Hint Association
**Learning:** Found an accessibility pattern issue across core form components (`Input`, `Textarea`, `Select`). They supported `label`, `error`, and `hint` props, but lacked internal `useId()` bindings to associate `<label htmlFor>` with the input `id`. Furthermore, error and hint messages were visually present but not programmatically linked via `aria-describedby` or `aria-invalid`, leaving screen reader users without proper context when navigating forms.
**Action:** Always implement `useId()` in custom form components to guarantee a unique `id` when `props.id` is missing. Use this ID to firmly link the `<label>`, input, and any contextual helper/error text using `aria-describedby` and `aria-invalid`. Additionally, decorative text like visual asterisks (`*`) for required fields should be hidden from screen readers using `aria-hidden="true"` to prevent redundant "star" announcements.
